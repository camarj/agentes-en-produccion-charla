## Desvíos
1. **Studio:** en mastra 1.31, `mastra studio` solo sirve la interfaz (puerto 3000 por defecto) y necesita un servidor Mastra aparte. El comando que levanta Studio + API en :4111 es `mastra dev`. Script: `"mastra:studio": "mastra dev --dir src/mastra"`. Para producción (T14) evaluar `mastra build` + `mastra start`.
2. **Rutas de la base:** `mastra dev` ejecuta el bundle desde `.mastra/output` o `src/mastra/public`, y `file:./data/mastra.db` no se resolvía. Se agregó `lib/rutas.ts` (`raizProyecto()` sube hasta la carpeta con `package.json` y `data/`; se puede forzar con `PROYECTO_RAIZ`, y `urlArchivo()` convierte rutas relativas en absolutas). T02 debe usar `urlArchivo` para `DATABASE_PATH`.
3. **Fuentes:** next/font expone `--font-plex-sans` / `--font-plex-mono`, y `@theme` las publica como `--font-sans` / `--font-mono` (evita una variable que se referencia a sí misma).
4. **Sonner:** se quitó `next-themes` del componente y se fijó `theme="dark"` (hay un solo tema).
5. `next.config.ts`: `serverExternalPackages: ['@mastra/*', '@libsql/client', 'libsql']` para que el bundler no empaquete los binarios nativos.
6. `pnpm-workspace.yaml`: `allowBuilds.esbuild: true` (pnpm 11 bloquea los scripts de instalación por defecto; tsx y mastra lo necesitan).
7. `data/.gitkeep` creado para que la carpeta exista y se resuelva la raíz.
